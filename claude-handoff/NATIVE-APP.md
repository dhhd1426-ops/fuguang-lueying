# 给 Claude Code：实现真正的原生 Android App

请基于此项目交付可用 Android Studio 打开的原生项目，最终可构建 APK/AAB。先读取根目录 HANDOFF.md，对照 public/ 的实际页面和交互。

## 目标与技术路径

采用 Kotlin + Jetpack Compose 实现原生布局与交互；视频背景用 Android Media3 播放。不要把 WebView 加壳当作完成原生重写。网页版是视觉和行为基线，应在需求一致的前提下转换为原生组件。若需 iOS，另建 SwiftUI + AVPlayer 工程，不宣称 Android 工程同时包含 iOS。

## 页面与模块

- 首页：全屏视频、浮光掠影两行标题、首页原文、导航、底部功能栏、时钟、显示设置。
- 纯净模式、播放暂停、前后台暂停恢复、减少动态效果。
- 掠影：使用 `public/content/luoying.json`，实现章节分类、标题/正文搜索、原始80条对话、字号、收藏、阅读进度、上一篇/下一篇。
- 网页中的“全屏”在原生中映射为阅读区域扩展/沉浸式阅读，不导航回首页。返回键逐层关闭当前窗口。
- 留言：使用 `claude-handoff/letters.json`，纵向单列卡片、右侧署名、悬浮完整正文、前后切换。
- 留言右上角仅一个主题开关。深色还原现有；浅色白与浅灰色块；主页保持原有。图标半月与太阳切换，主题从开关位置向外扩散。
- 关于和作品署名原文保持一致。
- 手记：原生本地编辑和保存。

## 数据、素材与状态

- `public/assets/scene.mp4` 可作为初版 Android assets 或 raw 资源；保持视频文件和画质，先做好生命周期管理，再评估首帧时间和耗电。
- 不直接尝试让 Android Media3 播放 .mpkg；它是原始壁纸归档。当前可播放素材为 scene.mp4。
- 用 DataStore 保存主题、字号和简单偏好；手记、收藏、章节进度可用 Room/DataStore，避免每次重组重复落盘。
- 避免在 UI 线程解码视频或解析大 JSON；视频播放不能触发整个页面逐帧重组。
- 打开阅读窗口时遵循网页版暂停背景；关闭时根据用户原本的暂停状态恢复。
- 错误、空内容、加载重试和权限拒绝都要有反馈。
- 浏览器本地数据不能自动读取进 App；若要迁移，另加用户主动导出/导入流程。

## 服务器与访问密码

现有网站采用服务端密码验证，不把服务器会话签名密钥硬编码进 App。`deploy-mainland/` 为同内容与素材提供 HTTPS 和会话保护。在线模式可向 `/unlock` POST 表单并携带正确 Origin，保存服务器 HttpOnly cookie 于网络 cookie 管理器，后续内容/视频请求带 cookie。桌面/移动网页继续使用原来的浏览器流程。

若采用离线打包内容，本地素材可以被提取，单一访问密码不能等同于服务器授权；必须与用户明确离线/在线内容的期望，再设计 App 登录与发布方案。

## 交付和验证

交付 Gradle wrapper、完整 Android 工程、构建步骤、调试 APK；正式发布签名密钥由用户自行管理，不放入源码/压缩包。不要伪造已上架。

验证：竖屏/横屏、系统字号、返回键多层窗口、主题切换保留阅读位置、后台恢复、音视频无意外声音、离线提示、低端机掉帧、收藏/手记进程重启后恢复。核心流程能在真实设备或模拟器完成后再宣称可运行。
